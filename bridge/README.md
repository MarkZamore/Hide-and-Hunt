# Адаптер сети Hide and Hunt

Для Minecraft 26.3 с Fabric Loader 0.20.1. Используются авторский
архив FaWrAGlY и его вложенный e4mc 6.2.3. Сборка адаптера читает и проверяет
их SHA256, затем компилирует отдельный Fabric JAR. Авторские файлы остаются
входами и не перепаковываются этим инструментом.

В авторском меню «Через e4mc» использует прежний выбор конкретного мира.
Для нового мира флажок выключен. Адаптер передаёт его значение только
синхронному вызову публикации из `Hosting.joined`. Обработчик e4mc читает
это значение до создания реле, учитывая также его штатный `hostEnabled`.
Ручной адрес, вход и завершение активного реле остаются в штатном e4mc.
Настройки и авторизация общего Steam-транспорта находятся в лаунчере.

В меню Hide and Hunt остаются локальные миры и вручную сохранённые адреса.
Автоматические Steam-миры видны в основном экране Minecraft «Сетевая игра».
Пакет отключает авторский запуск LAN-сканера и запасной UPnP. Стартовый
флажок, его пояснение и сообщение после открытия мира находятся в адаптере.

Адаптер требует исходные байты пяти авторских классов по SHA256, в том числе
e4mc mixin, и однозначные сигнатуры/точки вызова после загрузки. При изменении
авторской версии обновить и заново проверить эти привязки. Остальные классы
игры, авторизации и e4mc адаптер не меняет.

```powershell
$env:JAVA_HOME = 'C:\Tools\jdk-25.0.2'
python -B bridge/build.py --client-jar <26.3.jar> --upstream <авторский.jar> --out <стенд>/lanminecraft-hide-and-hunt-bridge-1.0.0.jar
```

Параметр `--libraries-root` позволяет переиспользовать уже проверенный кеш
библиотек. По умолчанию кеш создаётся рядом с выходным JAR. Библиотеки
компиляции берутся из официального Maven Fabric по SHA256 из `inputs.json`.
Сборка запускает проверку фактических авторских классов и обеих веток выбора,
включая освобождение области после ошибки, сохранность ручного списка и
отсутствие автоматического LAN-сканирования. Она не устанавливает сетевое
соединение и не подменяет запуск клиента.
